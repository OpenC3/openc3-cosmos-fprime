# F Prime CFDP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an operator push files to, and pull files from, an F Prime v4.4 deployment's `CfdpManager` using the unmodified OpenC3 CFDP plugin and CFDP GUI. A committed F Prime 4.4.1 container proves it end to end.

**Architecture:**
- **Packet carrier:** this plugin's FPRIME target gains a `CFDP_PDU` command and telemetry packet. Each carries one raw CFDP PDU behind the CCSDS header and the `00 03` (`FW_PACKET_FILE`) descriptor. The CFDP plugin's `cmd_info`/`tlm_info` point at them.
- **Downlink protocol:** the file-downlink protocol stops feeding CFDP PDUs to the legacy file assembler.
- **Parser fix:** command string parameters get the F Prime length prefix, so `CFDPMANAGER.SENDFILE` (the pull mechanism) actually works.
- **Test deployment:** a Dockerfile builds F Prime v4.4.1's Ref deployment, patched to use the `FileHandlingCfdp` subtopology and a TCP server comm driver.

**Tech Stack:**
- Python 3.12, the `openc3` Python package and pytest.
- Docker; F Prime v4.4.1 (CMake, `fprime-util`, FPP).
- The OpenC3 CFDP plugin (Ruby/Rails, unchanged).

**Spec:** `docs/superpowers/specs/2026-10-17-fprime-cfdp-design.md`

## Global Constraints

- **Do not modify** `/Users/jmthomas/Development/openc3-cosmos-cfdp` or `openc3-cosmos-tool-cfdp`.
- **Byte order:** all wire values are big-endian.
- **CFDP framing:** CFDP PDUs travel on APID 3 with a U16 descriptor `0x0003` before the PDU, in both directions.
  - A CFDP PDU is distinguished from a legacy `Fw::FilePacket` by `(first_pdu_byte >> 5) == 1`.
- **Gating:** `CFDP_PDU` packets are generated only when the dictionary has a CfdpManager and the headers are `SPACE_PACKET`. Dictionaries without one must not gain any CFDP packets.
- **String fix exception:** the string-parameter fix applies to all commands in both header modes. That is the one intended change to existing generated output.
- **Protocol order:** the file-downlink protocol stays the last READ protocol (`tests/test_plugin_txt.py`).
- **No new runtime dependencies.**
- **File headers:**
  - New source files start with the repo's MIT header (`# Copyright 2026 OpenC3, Inc.` … `# See LICENSE.md file in the project root for details.`).
  - Generated files start with `# This is a file generated by fprime_parser.py` / `# Do not edit directly`.
- **Pinned F Prime:** nasa/fprime tag `v4.4.1`.
- **F Prime defaults:**
  - CfdpManager `LocalEid` = 42; COSMOS entity = 100 (`FileInDefaultDestEntityId`).
  - Modular checksum; no PDU CRC.
- **Link defaults:**
  - TCP port 50000, SCID 0x44, TC VCID 1, 1024-byte TM frames, CRC on, no randomization.
  - The deployment is the TCP **server**.
- **Branch and commits:**
  - Work on `feature/data-products` (this builds on that branch).
  - Commits use conventional style (`feat(parser): …`, `test(...)`, `docs: …`) and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Tests:** `.venv/bin/python -m pytest tests/ -q`

## Review Focus

1. **Empty or 1-byte APID-3 payload:** the downlink protocol must pass it through with no exception and must not treat it as CFDP. Pinned in Task 3.
2. **Empty string command argument** (e.g. `DESTFILENAME ''`): it must encode as a zero length prefix with no characters, not as padding. Pinned in Task 1.
3. **String inside a command struct or array:** each element gets its own length prefix. Pinned in Task 1.
4. **FileDownlink's own `SendFile` command** (no `cfdpClass` argument) in a dictionary must **not** trigger CFDP packet generation. Pinned in Task 2.
5. **A Class 2 PDU sized at `maximum_file_segment_length`** must fit in one TC frame. If it doesn't, the TCTF protocol raises and every push fails. Pinned by the computed value in Task 6 and the wire check in Task 6, step 5.

- the space packet costs 6 + 2 bytes;
- the PDU header is 4 + 1 + 4 + 1 bytes;
- the FileData offset is 4 bytes.

That leaves at most 995 bytes of data, so 960 leaves margin.

Also state:
- **Pull example:** `cmd("FPRIME <SENDFILE command> with CHANNELID 0, DESTID 100, CFDPCLASS CLASS_2, KEEP KEEP, PRIORITY 0, SOURCEFILENAME '/files/medium.bin', DESTFILENAME 'medium.bin'")`. Use the real generated names. The pulled file lands at the CFDP plugin's `root_path/medium.bin`.
- **Push example:** the GUI and `cfdp_put(destination_entity_id=42, source_file_name='medium.bin', destination_file_name='/files/uplink/medium.bin')`.
- **Not supported:**
  - Class 1 closure and proxy put / remote get (GUI pull)
  - directory listing
  - running FileUplink/FileDownlink and CfdpManager in one deployment
- **Pointer:** to `fprime-test/README.md`.
